# omnilimit specification, version 1

Every omnilimit port must behave as described here. The JSON files in `vectors/` are the
normative test of that behaviour: a port conforms when it passes all vectors for its tier.
They are generated by `tools/gen_vectors.py`, an independent implementation, so no port
validates itself.

## Algorithm

A single algorithm, GCRA expressed as a meter on integers. There is no floating point.

A policy has `limit` (L), `window_ms` (W, at least 1000) and `burst` (B, default L).
Each request adds `W` units, the meter drains `L` units per millisecond, and:

```text
C     = B * W              capacity
drain = ceil(C / L)        time for a full meter to empty

t     = max(now, ts)
lvl   = max(0, level - min(t - ts, drain) * L)

if lvl + W <= C:   level = lvl + W; ts = t; expire after drain; allowed
else:              denied, and nothing is written
```

Public values:

```text
remaining      = floor((C - level) / W)
reset_ms       = ceil(level / L)
retry_after_ms = ceil((lvl + W - C) / L)     denied only
```

- A policy is invalid when any value is not a positive integer, `W < 1000`, or
  `2*B*W + L > 2^53 - 1`. Every intermediate value therefore fits in an IEEE double.
- Ports compute `C` and `drain` once. Store scripts only add, subtract, multiply and compare,
  which is why the same script gives the same answer from any language.
- Denials never write, so a retry storm cannot extend the wait.
- `t = max(now, ts)` means a clock moving backwards never refunds quota.

**Peak rate.** This is a rate, not a counter that resets. `5` per minute with burst 5 can admit
`B + L - 1 = 9` requests in one minute. If you need fewer, lower `burst`.

## Peek and reset

Two operations sit next to the hit. They change nothing above, and stores of tier `exact` and
`local` must support both. An `approximate` store cannot, and the limiter raises a type error
(a configuration mistake, not a store failure) when asked.

**Peek** returns the decision a hit would get now, and never writes:

```text
t     = max(now, ts)
lvl   = max(0, level - min(t - ts, drain) * L)
allowed = lvl + W <= C;    level reported = lvl;    ts reported = stored ts (now if absent)
```

The public values use the formulas above with `level = lvl`. When allowed, `remaining` therefore
counts the request being asked about, and the effective window is `reset_ms`. A denied peek
equals a denied hit. A peek is advisory: a concurrent hit can take the last unit, so the hit that
follows is still the authority. It neither extends a bucket's expiry nor refreshes its recency.

**Reset** deletes the bucket. The next hit or peek behaves as if it never existed. Resetting a
missing bucket is not an error. A reset that fails or times out is reported as such, and does
not follow `open`/`closed`: no request is being decided.

Together they express a limit that counts only failures, such as a login lockout: peek before
the work and refuse when denied, hit when the work fails, reset when it succeeds.

Sequence vectors mark these steps with `op: "peek"` or `op: "reset"`; a step without `op` is a
hit. Reset steps have no `expect`.

## State format 1

Key: `ol:1:<scope>:<L>-<W>-<B>:<hash>`, where `hash` is the first 32 hex characters of
`SHA-256(salt || 0x00 || id)`, using UTF-8.

- The hash bounds key length and keeps raw IPs out of the store.
- The policy is part of the key, because levels are measured in units of `W`. Changing a limit
  starts a new counter rather than misreading the old one.
- `scope` matches `^[A-Za-z0-9._-]{1,64}$`.

Peek uses `spec/scripts/redis/peek.lua` and `omnilimit_peek_v1` (`spec/scripts/postgres/002_peek.sql`,
which takes no lock). Reset is `DEL` in Redis and `DELETE` in Postgres.

| Store | Layout | Clock |
|---|---|---|
| Redis, Valkey | Hash `{l, t}` with `PEXPIRE drain` | `TIME` |
| Postgres | `omnilimit_state(key, level, ts_ms, expires_at_ms)` | `clock_timestamp()`, read after the row lock |
| Durable Objects | One object per key: `{level, ts, expiresAt}` | `Date.now()` |

The client's clock is never used, so skew between application servers cannot affect limits.
An injected `now` exists only for conformance vectors; with it, Redis does not set a TTL.

## Tiers

| Tier | Promise | Vectors | Stores |
|---|---|---|---|
| `exact` | Atomic and shared | `sequence`, `concurrency`, plus core kinds | Redis, Valkey, Postgres, Durable Objects |
| `local` | Exact per process; N instances allow about N times the limit | `sequence`, plus core kinds | Memory |
| `approximate` | Only allowed or denied; `remaining` and `reset` are `null` | `contract`, `failure` | Cloudflare rate limit binding |

Every decision reports its tier. Workers KV is not supported: it is not atomic, so it cannot
keep any of these promises.

"Identical" applies to `exact` and `local`. An approximate store follows its provider's model.

## Store failure

A store error, a timeout or a missing binding is a store failure. There is no default policy:
callers must choose `open` or `closed`.

| Mode | allowed | reason | status | Headers |
|---|---|---|---|---|
| `open` | true | `store_error` | none | none |
| `closed` | false | `store_error` | 503 | `Retry-After: 1` |

## Client IP

- `xff` with `hops`: split on commas, trim, take the entry `hops` positions from the right.
  Anything to the left of what your own proxies appended is client controlled.
- A chain with `hops` entries or fewer gives `null`. It never falls back to the first value.
- An invalid value in the chosen position gives `null`.
- IPv4 uses strict decimal octets. IPv6 follows RFC 5952, zone identifiers are rejected, and
  IPv4-mapped addresses become IPv4.
- Masking keeps an IPv6 network prefix (64 bits by default in key helpers). IPv4 is unchanged.

| Preset | Reads | Trust it only if |
|---|---|---|
| `cloudflare` | `CF-Connecting-IP` | The origin only accepts traffic from Cloudflare |
| `cloud-run` | XFF, `hops: 0` | Cloud Run is reached directly |
| `cloud-run-lb` | XFF, `hops: 1` | One Google load balancer is in front |
| `vercel` | `X-Vercel-Forwarded-For` | The app only runs on Vercel |
| `direct` | TCP peer | Nothing proxies the app |

Verify these against your deployment. A preset cannot detect a topology it does not match.

## Headers

Profiles are versioned because the IETF document is still an Internet-Draft.

`draft-11` targets draft-ietf-httpapi-ratelimit-headers-11:

```text
RateLimit-Policy: "<scope>";q=<L>;w=<ceil(W/1000)>
RateLimit: "<scope>";r=<remaining>;t=<ceil(effective/1000)>
```

The effective window is the retry time when denied, the time until the next unit when
`remaining` is 0, and otherwise `reset_ms`. `legacy` sends `X-RateLimit-Limit`,
`X-RateLimit-Remaining` and `X-RateLimit-Reset` (seconds, as a delta). `Retry-After`
(`ceil(retry_after_ms/1000)`) is always sent on denial, in every profile including `none`.

## Vector kinds

| Kind | Tests |
|---|---|
| `sequence` | Decisions, public values, headers and raw state, step by step |
| `key` | Key derivation |
| `ip` | Client IP strategies, canonical form and masking |
| `failure` | Each fault with each failure mode |
| `concurrency` | 200 simultaneous hits allow exactly `burst` |
| `contract` | Policy and scope validation, and the approximate decision shape |

Changing the meaning of a vector requires a new spec version.
